## Что умеет

- Выдаёт 0–4 перка или полную экипировку: предмет или способность, аддоны,
  подношение.
- Перк можно закрепить, чтобы он пережил следующий ролл, или перебросить
  один слот, не трогая остальные три.
- Выбор персонажа гарантирует его обучаемые перки или решает, чья
  способность выпадет.
- Три способа посмотреть на ролл: обычная сетка, воронка, которая раздаёт
  билд картами, и слот-машина.
- Управление пулом: поиск, теги, избранное, массовое включение и выключение,
  фильтр аддонов сразу по нескольким убийцам.
- Билд можно отправить ссылкой, скачать картинкой или отдать в OBS как
  браузерный источник.
- По восемь готовых билдов на роль — на случай, когда из трёхсот перков
  выбрать нечего.
- Испытание дня (одинаковый билд для всех в пределах суток по UTC), «Королевская
  битва» (билды выбывают по мере использования), статистика роллов и история
  последних двадцати.
- RU/EN везде: названия и описания берутся с вики, а не переводятся вручную.
- Ставится как приложение и работает офлайн.

## Клавиши

| Клавиша         | Действие              |
| --------------- | --------------------- |
| `Space`/`Enter` | Новый билд            |
| `1`–`4`         | Перебросить этот слот |
| `C`             | Скопировать билд      |
| `S`             | Скопировать ссылку    |

Пока вы печатаете или открыт диалог, горячие клавиши молчат и никогда не
перехватывают браузерные сочетания.

## Откуда берутся данные

`data/perks.json` и файлы экипировки генерируются, а не пишутся руками:

```bash
npm run scrape:perks
npm run scrape:loadout
```

Оба скрипта читают вики через MediaWiki API и складывают иконки в `public/`.
Иконки кэшируются по исходному URL, поэтому перерисованная иконка подхватится
на следующем запуске, а не останется устаревшей копией.

Раз в неделю, по понедельникам, GitHub Action прогоняет оба скрипта и, если
на вики что-то изменилось, открывает PR. Если ждать понедельника не хочется,
запустите **Update DBD perk and loadout data** вручную во вкладке Actions:
влитый PR сам задеплоит сайт.

Если скрейп вернул заметно меньше перков, чем в прошлый раз, он падает, а не
публикуется — сбой вики не должен молча опустошить пул.

## Разработка

```bash
npm install
npm run dev        # localhost:3000
npm run lint
npm run build      # статический экспорт в out/
npm test           # юнит-тесты
npm run test:e2e   # сначала собирает, потом гоняет Playwright по экспорту
```

Про тесты стоит знать две вещи.

`test:e2e` сначала собирает проект и работает со статическим экспортом на
порту 3100, а не с `next dev`: деплоится именно экспорт, а dev-сервер,
забытый на 3000, невозможно принять за него по ошибке. **Если сборка упала,
тесты пройдут по устаревшему `out/` и «зазеленеют» по ложной причине** —
поэтому не заглушайте вывод сборки в `/dev/null`.

Набор разделён по тому, что реально отличается: десктоп проверяет поведение,
`e2e/mobile.spec.ts` — только переполнение, размер целей нажатия и высоту
модалок, а `e2e/viewports.spec.ts` замеряет вёрстку от телефона 360px до 4K.
Правильность самого ролла проверяется один раз, а не на каждом устройстве.

## Оверлей для OBS

OBS рисует браузерный источник в отдельном профиле Chromium: ни
`localStorage`, ни `BroadcastChannel` с вашим обычным браузером не общие.
Поэтому у оверлея есть второй канал: основная вкладка публикует билд в
Firebase под случайным восьмизначным кодом комнаты, а оверлей его читает
(`lib/obs-sync.ts`).

Настраивать ничего не нужно — рабочий конфиг лежит в `lib/firebase.ts`, а
если Firebase недоступен, локального канала хватает для второй вкладки в том
же браузере.

Если вы форкнули проект и хотите свою синхронизацию, создайте Realtime
Database, вставьте свой `firebaseConfig` в `lib/firebase.ts` и ограничьте
запись восьмизначными кодами:

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "obs-rooms": {
      "$room": {
        ".read": "$room.length == 8",
        ".write": "$room.length == 8 && newData.hasChildren(['role', 'perks', 'language', 'updatedAt'])"
      }
    }
  }
}
```

Конфиг веб-приложения Firebase не секрет: доступ ограничивают эти правила, а
не сокрытие ключа.

## Как помочь

Issues и PR приветствуются. Перед PR прогоните `npm run lint`,
`npm run build` и `npm run test:e2e` — CI запускает те же три команды.

Два места, где легко ошибиться:

- **Генерируемые файлы.** Всё, что создают скрейперы (`data/perks.json`,
  `data/items.json`, `data/addons.json`, `data/offerings.json`, файлы `*-ids`
  и `*-icon-sources`, `data/author.json`), перезапишется на следующем
  запуске. А вот ручные переводы — `data/translations.ru.json`,
  `data/character-translations.ru.json`,
  `data/overrides/perks.json` и `data/overrides/loadout.json` — редактируются
  напрямую, так и
  задумано.
- **Скриншоты.** Если поменяли интерфейс, `npm run capture:screenshots`
  пересоберёт `docs/screenshots/` (скрипту нужен dev-сервер на порту 3000).
