## Открыть

### [flexeykindev.github.io/dbd-perk-randomizer](https://flexeykindev.github.io/dbd-perk-randomizer/)

Скачивать ничего не нужно. Работает в браузере на компьютере и телефоне.

Чтобы поставить как приложение, которое работает и офлайн:

1. Откройте сайт в Chrome, Edge или Safari.
2. На компьютере нажмите значок установки в адресной строке. На телефоне
   откройте меню «Поделиться» или меню браузера и выберите **На экран «Домой»**.
3. Запускайте из меню «Пуск» или с домашнего экрана.

**Удалить:** как любое другое приложение, или уберите значок с домашнего экрана.

## Что умеет

<img src="docs/features.svg" alt="Возможности: 321 перк, 932 аддона, закрепление и переброс, раскрытие воронкой или слотами, скины оверлея OBS, испытание дня, королевская битва, ссылка или картинка, EN и RU офлайн" width="100%">

А ещё: выбор персонажа гарантирует его обучаемые перки или решает, чья
способность выпадет; по 4 готовых билда на роль; статистика и история роллов;
управление пулом с поиском, тегами, избранным и фильтром аддонов сразу по
нескольким убийцам.

### Недавно добавлено

- Скины оверлея OBS: фон «Воронка» или «Слоты», рамка карт «Ритуал» или
  «Слоты», с анимацией или без.
- Появления «Раздача» и «Вращение». Рамка «Слоты» стала настоящим барабаном,
  который останавливается слева направо.
- Значения патча 10.1.1 для «Скрытого союза» и «Бессонницы», раньше вики.
- Билд и кнопка генерации теперь видны на ноутбуке без прокрутки, а все
  диалоги помещаются на экран телефона.

### Клавиши

| Клавиша         | Действие              |
| --------------- | --------------------- |
| `Space`/`Enter` | Новый билд            |
| `1`–`4`         | Перебросить этот слот |
| `C`             | Скопировать билд      |
| `S`             | Скопировать ссылку    |

Пока вы печатаете или открыт диалог, горячие клавиши молчат и не перехватывают
браузерные сочетания.

## Оверлей для OBS

1. На сайте нажмите **Оверлей OBS** и скопируйте ссылку.
2. В OBS добавьте **Браузер** (Browser Source) и вставьте её.
3. Роллите на сайте. Оверлей на стриме обновится сам.

Всё настраивается в диалоге и сохраняется в ссылке:

| Настройка | Варианты                                   | В ссылке |
| --------- | ------------------------------------------ | -------- |
| Фон       | transparent, dark, vortex, slots           | `bg=`    |
| Рамка     | plain, ritual, slots                       | `frame=` |
| Движение  | live, still                                | `fx=`    |
| Появление | rise, drop, flip, glide, deal, spin, none  | `anim=`  |

Старая ссылка без этих параметров выглядит ровно так же, как раньше.

## Приватность и сеть

- Без аккаунтов и без аналитики.
- **Firebase** нужен только для двух вещей: оверлея OBS, который публикует
  билд под случайным кодом комнаты, и счётчика испытания дня, это одно
  анонимное число в сутки. Если не пользуетесь ни тем, ни другим, ничего не
  отправляется.
- Трейлер под доской встроен с YouTube.

### Запуск

```bash
npm install
npm run dev        # localhost:3000
npm run lint
npm run build      # статический экспорт в out/
npm test           # 206 юнит-тестов
npm run test:e2e   # сначала сборка, потом 205 тестов Playwright по экспорту
```

`test:e2e` работает со статическим экспортом на порту 3100, а не с `next dev`,
потому что деплоится именно экспорт. Если сборка упала, тесты пошли бы по
устаревшему `out/`, поэтому сервер отказывается отдавать экспорт старше
исходников (`E2E_ALLOW_STALE=1`, чтобы обойти).

Набор разделён по тому, что реально отличается: десктоп проверяет поведение,
`e2e/mobile.spec.ts` проверяет переполнение, цели нажатия и высоту модалок, а
`e2e/viewports.spec.ts` замеряет вёрстку от телефона 360px до 4K.

### Откуда берутся данные

<img src="docs/pipeline.svg" alt="Вики, еженедельный скрейп, проверка, пулл-реквест, GitHub Pages" width="100%">

`data/perks.json` и файлы экипировки генерируются:

```bash
npm run scrape:perks
npm run scrape:loadout
```

Оба скрипта читают вики через MediaWiki API и складывают иконки в `public/`.
Иконки кэшируются по исходному URL, так что перерисованная иконка подхватится
на следующем запуске.

`.github/workflows/update-perks.yml` запускается по понедельникам: английский
скрейп, русские названия и описания, линт, юнит-тесты и сборка, потом PR. Сам
он вливается, только если добавились новые записи, старые не изменились и
проверки прошли. Если скрейп вернул заметно меньше перков, чем в прошлый раз,
он падает, чтобы сбой вики не опустошил пул.

Вики может отставать от патча. `scripts/check-patch-notes.ts` читает Steam
news API и отмечает в PR патч BHVR, вышедший после последнего скрейпа.
Исправления кладутся в `data/overrides/perks.json`: следующий скрейп их
запекает, а когда вики догонит, они просто перестают что-то менять.

### Синхронизация с OBS

OBS рисует браузерный источник в отдельном профиле Chromium, без общего с
вашим браузером `localStorage` и `BroadcastChannel`. Поэтому основная вкладка
ещё и публикует билд в Firebase под случайным восьмизначным кодом комнаты, а
оверлей его читает (`lib/obs-sync.ts`). Если Firebase недоступен, вторая
вкладка в том же браузере всё равно работает.

Для своего деплоя создайте Realtime Database, вставьте свой `firebaseConfig` в
`lib/firebase.ts` и опубликуйте эти правила (на них работает живой сайт).
Комната доступна только по коду, список кодов получить нельзя, а счётчик дня
растёт только на единицу:

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "obs-rooms": {
      "$room": {
        ".read": "$room.matches(/^[A-HJ-NP-Z2-9]{8}$/)",
        ".write": "$room.matches(/^[A-HJ-NP-Z2-9]{8}$/)",
        ".validate": "newData.hasChildren(['role', 'language', 'updatedAt'])"
      }
    },
    "daily-challenge": {
      "$day": {
        "count": {
          ".read": true,
          ".write": "$day.matches(/^[0-9]{4}-[0-9]{2}-[0-9]{2}$/)",
          ".validate": "newData.isNumber() && newData.val() == (data.exists() ? data.val() : 0) + 1"
        }
      }
    }
  }
}
```

Не оставляйте базу в тестовом режиме Firebase: её может читать и менять кто
угодно, а через 30 дней она закрывается целиком. Конфиг веб-приложения не
секрет, доступ ограничивают правила.

Еженедельная чистка комнат (`scripts/prune-obs-rooms.ts`) должна получать
список комнат, поэтому работает только с секретом репозитория
`FIREBASE_DB_SECRET`, а без него пропускается.

### Как помочь

Перед PR прогоните `npm run lint`, `npm run build` и `npm run test:e2e`. CI
запускает те же три команды.

- **Генерируемые файлы.** Всё, что пишут скрейперы (`data/perks.json`,
  `data/items.json`, `data/addons.json`, `data/offerings.json`, файлы `*-ids`
  и `*-icon-sources`, `data/author.json`), перезапишется на следующем запуске.
  Правьте `data/translations.ru.json`, `data/character-translations.ru.json`,
  `data/overrides/perks.json` и `data/overrides/loadout.json`.
- **Скриншоты.** После изменений интерфейса `npm run capture:screenshots`
  пересоберёт `docs/screenshots/` (нужен dev-сервер на порту 3000).

### Деплой

Статический экспорт, который `.github/workflows/deploy.yml` публикует на
GitHub Pages при каждом пуше в `main`.

Next.js, TypeScript, React, Tailwind CSS, Framer Motion, WebGL, Firebase
Realtime Database, cheerio и sharp для скрейперов, Playwright.
